# 身份、限流与签到边界

## 校园身份核验

新注册账号默认为未核验。报名必须有 `verified_at`；管理员在「活动管理 → 校园身份核验」按用户名查找，先在线下核对学校名册或证件，再录入学号。学号使用唯一索引，同一学号不能绑定多个账号，普通学生不能自行填写或修改核验结果。公开学生接口仅返回 `verified` 布尔值，不暴露学号。

该流程是人工核验记录，不是已经接入学校 SSO 或教务系统。管理员若接受伪造材料或错误录入，系统不能识别；同一人使用不同虚假身份仍需要线下制度约束。演示学生的 `DEMO20260001` 是虚构测试身份，不代表真实认证。

## 短时签到码

管理员仅可在活动开始前 30 分钟至结束期间生成签到码。码由 `SecureRandom` 生成，有效期至多两分钟，且不能超过活动结束时间。生成新码立即替换旧码；无有效期的旧版本固定码不会被接受。获取码为 GET，生成/轮换为 POST + CSRF。签到须已报名且未取消、未签到。

短时码能缩短转发时间，不能证明持码人到场。仍可在有效窗口内转发、共享账号或代操作。应由现场管理员核对学生证与到场人员，再展示签到码；更强方案需要真实学校 SSO、单人凭证或现场工作人员逐人核验，本项目不宣称消除代签。

## 接口限流

单进程内存固定分钟窗口：

| 范围 | 默认上限 / 分钟 |
| --- | --- |
| 登录来源 IP | 20 |
| 登录用户名 | 10 |
| 注册来源 IP | 5 |
| 已登录账号写请求 | 60 |
| 已登录账号签到请求 | 10（同时计入写请求） |

超限返回 429 与 `Retry-After: 60`。不采信客户端 `X-Forwarded-For`。窗口过期清理，最多保留 10000 个键，达到上限时拒绝新键。`app.rate-limit-multiplier=0` 仅供隔离测试关闭限流；正常运行默认 1。

内存限流在重启后清空，多实例不共享计数；校园 NAT 下会共享 IP 限额，固定窗口边界也允许短时突发。公网多实例应在可信网关或共享存储中实现统一策略。这些措施降低滥用成本，不能保证一人一账号。

## 登录过期与提交结果

HTTP 401 清除浏览器中的用户、报名、管理页与旧请求结果，提示重新登录；成功登录后恢复原页面，不自动重放写操作。403 不触发盲目重试。提交成功与后续查询刷新分开提示：刷新失败不会把已提交操作描述为提交失败，避免误导用户重复操作。
